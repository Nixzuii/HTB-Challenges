## 1. Summary

Meow is a beginner machine that introduces the basic penetration testing workflow: connect to the lab VPN, scan the target, identify an exposed service, and gain access. The target exposes **Telnet (port 23)**, and the `root` account has **no password set**. Logging in as `root` with a blank password gives full system access, and the flag is read from root's home directory.

**Vulnerability:** Misconfigured service with weak authentication (an empty password for `root` over Telnet).

**Attack path:**

```
OpenVPN connection → Nmap scan → Telnet found on 23/tcp → Login as root (blank password) → Read flag.txt
```

## 5. Enumeration

### 5.1 Port Scanning with Nmap

Next I scanned the target to find open ports. Hosts on HTB often don't respond to ping probes, so I used `-Pn` to skip host discovery. A first attempt at `-sN` (a TCP NULL scan) failed because it needs raw sockets and therefore root privileges, so I re-ran it with `sudo`.

```bash
nmap -Pn 10.129.188.156
sudo nmap -sN 10.129.188.156
```

**Result:**

```
PORT        STATE         SERVICE
23/tcp      open|filtered telnet
4998/tcp    open|filtered maybe-veritas
18040/tcp   open|filtered unknown
30951/tcp   open|filtered unknown
54328/tcp   open|filtered unknown
```

<img width="1495" height="812" alt="image" src="https://github.com/user-attachments/assets/3e3bd21f-579f-4659-acb0-05504c99fa4e" />

> **Note:** A NULL scan (`-sN`) can't tell "open" from "filtered", so every result is reported as `open|filtered`. Port **23/tcp (Telnet)** is the one that matters here, since it is a well-known, unencrypted remote login service. The other ports are high, unknown ports that are likely noise from this scan type. A standard SYN scan (`nmap -sS -p- <IP>`) or a version scan (`-sV`) would give cleaner results.

## 6. Exploitation: Telnet Login as Root

Telnet is an old, **unencrypted** protocol for remote command-line access. It is insecure because credentials and session data travel in plaintext, and it is only safe if properly authenticated. Here, authentication was effectively absent.

I connected to the service on port 23:

```bash
telnet 10.129.188.156 23
```

The target displayed the Hack The Box banner and a `Meow login:` prompt. My attempts, in order:

1. A mistyped entry (`ls`, which came through as `^[[Als`) → **Login incorrect**
2. `meow` → **Login incorrect**
3. `root` → **Logged in with no password prompt**

Logging in as `root` gave a shell on the target, running Ubuntu 20.04.2 LTS.

![Telnet login as root](images/05-telnet-root-login.png)

## 9. Lessons Learned & Remediation

**Key takeaways**

- Always enumerate first. A port scan revealed the Telnet service, which was the entire way in.
- Try default and blank credentials (`root`, `admin`, `administrator`) on exposed login services.
- Scan type matters. `-Pn` avoids missed hosts, and `-sN` needs root and gives ambiguous results.

**How to fix this**

| Issue | Recommendation |
|---|---|
| Telnet exposed | Disable Telnet and use **SSH** instead (encrypted) |
| Root has a blank password | Enforce strong passwords; set a password or lock the account (`passwd -l root`) |
| Direct root login allowed | Disable direct root login and use a regular user with `sudo` |
| Open services reachable from the network | Restrict with a firewall and expose only what is needed |
